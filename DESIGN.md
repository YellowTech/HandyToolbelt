# HandyToolbelt interface

A focused native Mac utility, honoring the user's explicit simple-UI brief. Use SwiftUI and AppKit controls, system typography, semantic colors, keyboard navigation, and system appearance. No decorative assets or web layer.

The window's native top bar places HandyToolbelt at the left and one right-aligned group of Gestures, Switcher, Snapping, Overlays, Power, Coffee, and a gear-only Global Settings pill at the far right. The gear retains an accessible label and tooltip. The main settings window uses a fixed 980pt content width, a default height of 800pt and a minimum height of 670pt. Height remains adjustable. All seven pills remain visible; there is no collapsed Tools menu. The native window title remains available to accessibility and the Window menu without a duplicate centered title. Every tab always has a filled pill and a fine border, including inactive tabs: a darker charcoal fill in dark mode and a darker warm neutral in light mode. The selected pill uses ochre text and border over the selection surface. Selected state is separate from availability: off tools use dimmer gray text and icons without an Off label on the pill, but their tabs stay clickable and explain how to enable them in Settings. Global Settings centralizes tool switches, Start at login, access, and restart. Its page heading is Global Settings; tool preferences belong in their own modules. Settings, Switcher, Snapping, Overlays, Power, and Coffee share a horizontally centered 760pt column with left-aligned contents; Gestures uses the full width for its split workspaces. The one menu-bar entry provides quick navigation, Coffee controls, restart, and quit. Its menu uses separators between tool navigation, Coffee controls, and app controls, without redundant disabled section headings. Its icon toggles the native menu: one click opens it, another closes it. Escape, outside clicks, and selecting a command dismiss it; releasing the closing click must not reopen it.

Gestures has persistent in-content Mappings / Gesture Gym / App Groups / Settings navigation and one shared device selector for mappings and gym. The Settings subtab contains shared gesture-toast and haptic defaults without a device selector or touch visualizer. Mappings use fixed columns: a 280pt saved-gesture sidebar on the left and the selected mapping editor on the right. Gym reserves 370pt for its settings column. Top-level tools and their workspaces lazily retain native controls for fast repeat navigation; leaving Gestures must preserve its workspace cache. Only the selected tool and workspace belong to the window, and detached previews cannot run their display clocks. Cached roots observe current selections, enablement, and settings, and reapply the theme and restart-disabled state at each native hosting boundary. Leaving Gestures ends shortcut recording and calibration. Native UI construction stays on the main thread; do not disguise it as asynchronous loading or eagerly create unvisited tools. Practice in Gym opens the selected gesture directly. A bottom touch surface shows live fingers and recognition feedback; actions do not dispatch while HandyToolbelt is frontmost. There is no separate testing switch. Permission notices link to the full recovery controls in Settings.

Switcher settings use a single native form for keyboard shortcut, List/Grid layout, and optional window previews, followed by the static chooser illustration. Scope and inclusion filters remain compatible configuration fields but are not exposed in this form. The chooser is a nonactivating panel showing real app icons, window titles, app names, and minimized/hidden state. Highlight one selection and keep ordering fixed during a choice. Grid arrows follow the visible columns; Tab keeps its linear order. A bare Shift tap steps backward on release; Shift–Tab continues to step backward without adding an extra step when Shift is released. Releasing the shortcut's held modifiers confirms as usual. Preview snapshots load on demand without delaying selection, use an icon fallback for unavailable or ambiguous windows, and stop when the chooser closes. Screen Recording access is requested only through the explicit preview permission control. Show loading, empty, closed-window, and permission states. No decorative assets or separate menu-bar icon. Keep implementation identity details in documentation rather than the settings flow.

The chooser controls include a fixed-height illustration that updates with List/Grid, Window previews, and a 75–150% Preview size slider visible only when previews are on. Reserve enough room for the largest illustrated rows and derive real chooser columns and keyboard navigation from the same geometry. Use fictional windows and authored vector thumbnails through the real chooser rows, with no discovery, captures, input handling, or animation. Snapping has its own top-level tab and Global Settings enable switch. Explain the separate-Spaces dependency in help and show an explicit automatically-disabled state when native tiling is available; its listener stays stopped and its tab is dimmed but remains clickable in that case. Its target outline never takes focus or intercepts clicks; respect the available screen area and the app's resize constraints.

The Settings permission panel reports access for the running app and separates Open Settings, Check Again, and Restart HandyToolbelt. Recovery instructions sit in a disclosure, with Reveal App to resolve stale or duplicate entries. Restart remains available after access is granted; the menu bar and app menu offer it too. Restart preserves saved settings and blocks while gym trial settings need applying or reverting. Review Gym Trials routes to a device with unapplied changes.

Preview setup is a compact sheet opened from the Screen & System Audio Recording controls in Global Settings. Guide Screen Recording access, then test a real window capture so macOS can present any direct-access confirmation. Do not claim the second prompt has an independently queryable permission flag. A successful capture is the readiness check. Begin only after an explicit setup action, continue when the user returns from macOS permission controls, and offer retry or the existing restart path if needed. Closing setup cancels its work. Keep OS prompts and system requirements truthful; do not promise to combine, suppress, or permanently approve them.

Keep editing in place. Gesture, optional corner modifier, and action form one readable chain. Use familiar shortcut glyphs and SF Symbols. Separators and space establish hierarchy. Reserve accent color for selection and live touch feedback. Empty, paused, permission-denied, unavailable-device, duplicate-binding and action-error states must be visible.

The gesture gym is an always-visible Gestures subtab, never a transient toolbar toggle. The left pane shows the practice gesture, trackpad diagram and immediate recognition feedback; the right pane keeps the hand angle and six-sample tip-tap calibration visible. Recognition feedback reserves two text lines and keeps a permanent finger/device row, including zero fingers. Recent attempts use an independent 160pt-high scrolling viewport even when empty; new results follow the latest position, while reviewing older results retains the visible attempt. Clearing history does not change the page height. Fine-tuning controls are created only when expanded. Show real contacts, trails, the rotated left/right axis, spacing boundary, movement tolerance, corner regions, and retained endpoints. Label finger roles and rejection reasons in text as well as color. Keep fine adjustments in a disclosure. A fixed Apply/Revert footer distinguishes trial and saved settings. Preserve per-device trial tuning across navigation; stop calibration when leaving the gym. Practice suppression and trial tuning apply only while Gym is selected and HandyToolbelt is frontmost. Background apps use saved tuning, app groups, corners, and enabled mappings. Do not publish visualization frames while another module is selected or the window is hidden.

Touch surfaces use Canvas drawing and redraw independently of settings, synchronized to the window's display up to 120 Hz. Gym diagnostic text and the press indicator have separate observation boundaries; position-only frames must not invalidate either settings form or the press indicator. Unchanged permission probes and idle clears publish nothing. A display sample publishes the drawing state at most once, including when touch and press state change together. Use an 8 ms position filter, with immediate touchdown/lift and no extrapolation. Keep raw trails, recognition, and calibration unchanged. Force-capable trackpads use an exponential size curve: firmer contacts grow more visibly, with a solid center and outlined translucent ring at fixed opacity. This is an uncalibrated pressure cue, never a force meter or gesture threshold; unsupported devices retain the usual ring. Clicks use green, force clicks purple, with a text label and a brief expanding ring in the readout to the right. Respect Reduce Motion with a stationary fading ring. Use real mouse events and macOS pressure stages, not raw-force thresholds. A preview surface opts into two-stage pressure only while the pointer is over it. Stop display work after lift and the bounded 650 ms feedback tail, stale input, or removal of the surface.

Haptic choices are Off, Light click, Click, Firm click, Double click, and Strong double. Use native system patterns and short sequences, never a claimed adjustable motor amplitude. Settings and the gym share the default and practice-feedback switch; mappings can override the default. Explicitly selecting a haptic pattern previews it after 400 ms; Off stays silent and a newer selection replaces the pending preview. Every picker retains a Test button with the same delay and a fixed-width waiting state. Opening a page, restoring configuration, or editing through the CLI must not trigger a preview. Cancel pending tests on navigation, pattern or availability changes, focus loss, and sleep. Disable testing without a connected Force Touch trackpad. Haptic choices save immediately, separately from detection trials. Pulse only for matched practice gestures, accepted calibration samples, or accepted mapped actions; do not pulse for rejected attempts. Cancel queued pulses when tools stop, settings change, focus changes, or the session sleeps.

Design exploration seed: 601e2d69. The simple native utility brief takes precedence over decorative catalog treatments; carry their useful discipline through precise alignment, visible state, compact controls, and spatial touch feedback. Code-first implementation uses real controls and actual hardware data.

## Warm Graphite · 0.7

The approved direction uses flat, warm surfaces: dark chrome/sidebar `#1D1D1A`, editor `#292925`, fields `#373732`, bone text `#ECEBE2`, readable secondary text `#B7B6AD`, restrained ochre `#D3B77A`, and quiet selection `#39362A`. Theme.swift owns semantic colors with a composed warm light fallback. Follow the system appearance; never force dark mode or introduce an appearance setting. Native titlebar and toolbar use the chrome surface. Native lists retain selection, keyboard navigation, and accessibility while drawing the quiet row background. Use system fonts, modest headings, six-point control corners and twelve-point surface corners. No gradients, glow, decorative cards, or new dashboard labels. Click and force-click feedback remain green and purple with text state.

Keep visible copy task-specific. Remove generic subtitles, repeated autosave reassurance, permanent color legends, haptic implementation explanations, and bottom explanatory paragraphs. Extended gesture, scoping, and haptic information belongs in native help or a small keyboard-accessible help popover. Preserve active errors, conflicts, missing/empty scope warnings, permission recovery, paused state, modifier identity, raw gym metrics, active calibration prompts/results, and the Apply/Revert distinction. Practice in Gym sits beside Active; compact mapping rows retain action and app scope. Idle pressure feedback says No touch; live touching, click, and force-click states report their actual state. Simplification must never remove a functional control.


Visual feedback uses two quiet, nonactivating Warm Graphite panels. Show Text is a mapping action with brief plain text and a 500 ms default; its preview works while actions are paused. Optional Gesture toasts default off and show recognition or the accepted mapping after focus/scope revalidation. Panels follow the pointer's display, align with the full display's horizontal center while staying within its visible frame, replace immediately, and expire with a cancellable single shot. Never intercept focus or mouse input. Sleep, session deactivation, and disabling Overlays dismiss feedback. Overlays remains independently available when Gestures stops.


## Overlays and local automation

Overlays has its own clickable tab and enable switch alongside Gestures, Switcher, and Snapping. Its compact workspace explains the purpose of centered text, toasts, and step progress, with explicit preview controls. Progress preview is a clearly labeled demonstration, independent of saved automations and centered text; leaving the page cancels it, and real progress takes precedence. Gestures → Settings contains shared gesture feedback; Global Settings keeps flat tool enable rows. The Overlays page’s Gesture Settings link opens this subtab directly. Gesture toasts state their Overlays dependency and preserve the saved preference when Overlays is off. Each mapping can opt out under Per-gesture overrides without changing the global preference. Its toast checkbox is disabled when automatic gesture toasts or Overlays are off, or when Show Text provides its own message. Gesture Settings offers a help popover and an explicit example preview that does not execute an action or change the automatic-toast preference. Keep each tool’s preferences and main workflows on its tab. Global Settings does not use tool-preference disclosures. Off tabs retain the existing enable hint. Keep the Warm Graphite surfaces and concise, task-specific explanations.

Multi-step feedback shares the top slot. Show the title, completion count, named step states, current message, and final outcome. Keep the active step visible without requiring interaction with the click-through panel. A running spinner, thin completion bar, and brief checkmark transition convey real progress. Keep the same view alive across updates; use short transitions, honor Reduce Motion, and stop motion when hidden or finished. Progress takes precedence over brief gesture toasts. Pin a session to its starting display, measure its content, clamp its panel to available screen space, and use bounded sessions with single-shot expiry. Disabling feedback never stops the automation itself or replays stale visuals when enabled again.

Global Settings contains an Automations & CLI section with saved definitions, a JSON editor with validation, and run/cancel controls. This belongs to the host, so it remains available with Overlays off. The gesture action picker can select a saved automation. A Copy CLI Path control exposes the bundled executable without changing shell configuration. A native Allow CLI control switch defaults off, explains same-user access without individual approvals, and stores its choice only on this Mac; keep automation editing and run/cancel controls usable while off. Show actual CLI availability with inline startup errors and Retry, and explain that disabling stops new commands while actions already started can finish.

Settings backup sits between Start at login and macOS Permissions in Global Settings. Use native Export/Import file pickers, a concise iCloud Drive explanation, and a disclosure for included data. An import review shows the filename, configuration counts, enabled tools, validation warnings, and expandable definitions before Replace Settings. Preserve current settings in a local backup first; show errors inline without dismissing or resetting unrelated preferences. Keep file-provider work off the main thread and make cancellation and stale-review handling explicit.


Coffee offers independent Prevent idle sleep and Keep display awake checkboxes in its tab and the menu bar. A question-mark popover explains the native power assertions equivalent to `caffeinate -i` and `-d`, without launching commands; the shared menu icon becomes a coffee cup while an assertion is held. Disabling Coffee releases assertions and clears both selections; re-enabling leaves both modes off. Selections reset on quit. Deliberate sleep and lid closure remain available.

Start at login is a single switch in Settings. Read its state from macOS; show approval guidance or errors only when relevant. Login registration is independent of JSON configuration and tool enablement. Automatic login launch keeps HandyToolbelt in the menu bar; manual launch and Restart open the main window.


Gesture stacks hold one corner contact to enter a scoped set of gestures. Start actions may hold Control, Command, Option, or Shift; the app releases owned keys automatically when the corner lifts or the session ends. Child gestures use the other fingers (tip-taps and tip-swipes use two to four additional fingers), and release actions run after automatic key release on every ending, including a disconnect or input error. Only one stack runs at a time, suppressing all other gesture mappings; stacks cannot nest. Start, child, and release phases support up to 32 actions, with up to 32 child gestures. Hold keys is available only in the start phase. Ordinary actions include Key press, System, AppleScript, Show Text, Automation, and Open App by bundle identifier.

Version 5 configuration adds `stacks`, `keyboardModifiers` requirements (`any` or an `exact` physical modifier set), and the `openApplication` action. Existing versions 1–4 migrate with empty stacks and unrestricted physical modifiers. Enabled stacks reserve their corner across overlapping device, app, and physical modifier scopes; ordinary corner mappings and other stacks must use disjoint scopes or modifiers. Disabled drafts report incomplete action warnings. App-specific ordinary mappings retain priority over Everywhere mappings.


Power uses a compact plug-to-Mac diagram with a battery branch in the shared bounded settings column. Static arrows show known charging, discharging, and battery assistance directions; unavailable and settling readings do not imply active flow. Nodes separate estimated Mac power, measured adapter input and adapter capacity. Battery details show cycle count, full/design capacities and estimated health. Health prefers rounded nominal capacity relative to design capacity, falling back to full charge capacity; help explains the source and that this is not a guaranteed copy of macOS Battery Health. Values come from read-only IOKit sources, with unknown data explicit and accessory batteries excluded. Live power refreshes every two seconds only while Power is visible and frontmost; elsewhere notifications update readings without periodic sampling. Disabling Power, sleep and screen lock stop monitoring. There are no history charts or stored readings. Charging links to macOS Battery settings; on Apple silicon with macOS 26.4 or later, visible instructions say to click the info button beside Charging and use the Charge Limit slider. HandyToolbelt does not set or enforce this limit. Toolbar labels keep a constant font weight across selection, with three additional points of vertical breathing room.

Permission requirements use compact clickable pills with text and check/error symbols as well as green/red color. Accessibility appears beside Gestures, Switcher, and Snapping enable switches; Screen & System Audio Recording appears beside Window previews. Missing Accessibility blocks a new enable transition, including through the CLI, but never prevents disabling or erases saved configuration. Clicking a requirement opens Global Settings, scrolls its control into view, and briefly highlights it; repeated navigation and cached views must work, and Reduce Motion skips movement. Central permission controls refresh without prompting; explicit preview setup reuses the two-stage wizard and remains available with Switcher disabled. The screen permission pill reports the queryable macOS grant only, not a promise about a future direct-capture prompt.

Global Settings groups Accessibility and Screen & System Audio Recording under macOS Permissions. Both share one permission-section layout: a stable heading with a green Enabled or red Not enabled badge, concise guidance, and Open System Settings / Check Again / Restart HandyToolbelt actions. Both use the same check-result feedback. Screen access adds Test Preview for its separate capture confirmation; this never runs automatically. Keep Accessibility recovery guidance conditional on missing access.

Gesture teaching uses finger diagrams: hollow circles rest, filled circles tap or move, and an orange circle marks a corner hold. How-to examples are separate from Live input, available in Mappings, the Gym, and stack children. Replay is explicit and bounded to three seconds, stops when hidden or inactive, and becomes a static illustration with Reduce Motion. Keep animation state local so playback does not rebuild surrounding settings. Finger controls name resting fingers for anchored gestures; total counts include a separate corner hold.

Long touch and Double tap use two to five fingers, or one to four free fingers with a corner hold or in a stack. Long touch recognizes once while held, without a pressure threshold; free fingers lift to rearm. Double tap requires a full free-finger lift between nearby taps. Only an applicable enabled Double tap mapping or the current practice target delays the corresponding single Tap. Fine-tune detection holds the two timing controls; no separate temporal-gesture settings page or repeat options. Teaching shows a stationary hold or tap–lift–tap–lift, with concise labels and the existing bounded playback. Deferred recognition is canceled on context, input-session, device, or modifier transitions, and uses a single cancellable deadline rather than polling.

The HandyToolbelt icon uses a solid rounded pouch, a broad belt, and two upright tools, with no slit between belt and pouch. The Dock icon places the ivory mark (#faf8f3) on a graphite tile (#302f2b); the menu-bar icon uses the same vector as a 16pt monochrome template within a fixed 16pt-wide click target. Coffee fits its active cup indicator proportionally inside a 16×16pt box and keeps the same 16pt-wide slot.

Switcher, Snapping, Overlays, Power, Coffee, and Global Settings place one short purpose sentence below the page title, with 6pt spacing, callout typography, and the secondary text color. Gestures keeps its workspace layout without an introductory subtitle.

Fresh installations start with all tools disabled; later launches retain saved enablement. Disabled tools share fixed icon, heading, and action geometry, with Open Settings above Enable this tool; input tools retain Accessibility gating. Mappings are ordered Everywhere first, then by app-group order, with up to three member app icons beside each group. New ordinary mappings start active with a complete Show Text example and an unused gesture; delete sits beside Active. The Switcher grid-size slider changes popup dimensions independently of preview size, and preview layouts retain small app icons beside app names.

Tip-tap anchors can move and then settle for the configured hold duration. Anchored gestures enforce a configurable maximum finger span and a trackpad rim exclusion for resting fingers. Double tip-taps support left/right/middle, including stack children; only applicable double mappings defer singles. Anchors and context must remain valid through the second tap or timeout. Snapping waits for drag release handling, verifies the final frame over spaced observations, and retries rollback at most three times while the original interaction remains valid.
